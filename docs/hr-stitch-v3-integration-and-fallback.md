# HRBP · Stitch v3 素材采用与备用方案

## 本轮已采用

- `meeting-room-editorial.png`：会议室背景。空间与光线可用，已作为会谈场景底图。
- `meeting-table.png`：透视木桌。已去除绿幕并作为前景层使用，桌面自然遮挡人物下半身。
- `xiaolin-guarded / hesitant / anxious / thinking / explaining / understood / trusting.png`：从新版 8 状态表拆分并去绿，已按固定面谈轮次自动切换。
- `xiaolin-neutral.png`：已处理并保留，供初始状态或后续回访场景使用。

以上素材位于 `public/assets/hr/`。React 继续控制人物状态、对话、实时纪要与流程，素材不包含业务逻辑。

## 本轮未直接采用

- 新版全身人物设定图：人物身份、脸型和服装与 8 状态人物不一致，且含大标题，只能参考。
- Stitch 整页 UI：仍有大块绿幕、整张人物表入镜、内容溢出和画布比例不统一，不能进入正式前端。
- Stitch 显示器：绿幕去除后仍有边缘模糊和灰色渐变。已经处理为 `monitor-shell-stitch-backup.png`，但目前不启用。

## 当前主方案

场景采用四层合成：

1. Stitch 会议室背景；
2. 当前轮次人物 PNG；
3. Stitch 木桌 PNG；
4. 我们自己的 HTML/CSS 正面电脑，屏幕内部继续运行真实 React UI。

这套结构不依赖 Stitch 生成完整页面，也不会因为素材更新而重写业务交互。

## 备用方案

如果 Stitch 下一轮仍无法稳定输出：

- 人物：继续使用本轮 8 张拆分素材，固定人物尺寸与锚点；必要时只挑 5 张最稳定状态，避免低质量状态破坏一致性。
- 表情变化：通过人物 PNG 切换、对话文本和微小位移表达，不再使用 emoji，不引入好感度或多结局。
- 电脑：永久保留现有 HTML/CSS 外壳。它可精确控制屏幕比例、内容裁切和响应式，无需位图显示器。
- 背景：保留现会议室；若住宅感仍明显，可在前端增加低对比度的玻璃隔断线、会议室门牌和吸音板，而不是重新依赖整页生图。
- 桌子：继续使用当前透明木桌；纹理或颜色问题可用 CSS 色相/亮度微调，不把桌面和 UI 烘焙到一张图中。
- 最终保底：即使不再获得任何新素材，当前四层合成也能完成完整固定对话、过程指导、实时纪要、组织行动和两周回访体验。

## 下一轮替换原则

新素材必须先通过“同一人物、独立文件、无绿边、人体结构正常、透明背景、无文字”六项检查，再替换 `public/assets/hr/` 中的同名文件。只要保持文件名和人物锚点，前端无需改业务代码。
